Built for hosting a world

Not a game storefront — an operator that stands up the dedicated server your players join.

  • Declare × Reconcile

    Apply a CR. The controller builds Deployment, PVC, ConfigMap, Secret, Service, and optional backups + Server Manager.

  • Direct UDP path

    Prefer a kube-vip LoadBalancer VIP. Envoy UDP rewrites client source and Satisfactory joins fail.

  • Join × Survive

    Players Direct connect to status.connectionAddress:7777 — you keep the cluster side.

How it works

Three steps from CRD to a running world.

  1. Install the operator

    kubectl apply -k config/default — CRDs, RBAC, and controller land in your cluster.

  2. Declare a SatisfactoryServer

    Set serverName, world name, and a LoadBalancer VIP. The reconciler wires the community image, storage, and passwords.

  3. Share the address

    Read status.connectionAddress and status.connectionPort, then Direct connect in-game.

Local / minimal PC

No Kubernetes required. Run the same official ghcr.io/robtme/satisfactory-server image with Docker Compose — then graduate to the operator when you want cluster hosting. Guide: docs/LOCAL.md. 

cd compose
cp .env.example .env   # set MAXPLAYERS / SKIPUPDATE
docker compose up -d
# Direct connect → 127.0.0.1:7777
docker compose down
  • Players 1–6 (official cap)
  • RAM ~8 Gi free recommended · official minimum 4 Gi
  • Ports 7777 / UDP game · 8888 / UDP beacon

Saves live under compose/data/. Cluster path (LoadBalancer VIP + CR) stays the production default.

Connect from inside Satisfactory

Once the CR is Ready, players join from the game client — not from kubectl. Full write-up: docs/CONNECT.md.

1. Read the address (admins)

kubectl get satisfactoryserver -n game-servers
# ADDRESS + PORT → status.connectionAddress / connectionPort

kubectl get satisfactoryserver satisfactory-server -n game-servers \
  -o jsonpath='{.status.connectionAddress}:{.status.connectionPort}{"\n"}'

Share connectionAddress:connectionPort (default port 7777 UDP). Example: 192.168.14.188:7777.

2. Direct connect

  1. Launch Satisfactory → use Direct Connect.
  2. Enter the VIP and port from status.
  3. Enter the world password from Secret key world-password, unless allowEmptyWorldPassword: true.

3. Passwords

  • world-password Join password — share with players
  • admin-password Server Manager / legacy admin — keep private 
kubectl get secret satisfactory-server-secrets -n game-servers \
  -o jsonpath='{.data.world-password}' | base64 -d; echo

kubectl get secret satisfactory-server-secrets -n game-servers \
  -o jsonpath='{.data.admin-password}' | base64 -d; echo

4. Why not Envoy?

Direct VIP is the reliable path. Envoy’s UDP proxy rewrites the client source to the Envoy pod IP — Satisfactory then fails with “network connection failed”. Set gateway.enabled: false and serviceType: LoadBalancer.

Recent/Public listings may show a WAN IP from EOS — prefer Direct for private operator worlds.

FAQ

Why does join fail behind Envoy Gateway?

Unreal sees the Envoy pod IP as the client source. Use a LoadBalancer VIP with gateway.enabled: false instead.

Do I need serverName?

Yes — the community image will not start without a Satisfactory Player ID (spec.serverName).

What happens if the world GUID changes?

The operator pins status.worldSaveGuid and refuses Ready on drift. Clear it only for an intentional wipe/rebuild.
